## 演练与转写

| 字段 | 来源 | 关联方式 |
| --- | --- | --- |
| rehearsal_id | 服务端创建演练 | 一次演练唯一业务记录 |
| goal_version／goal_snapshot | 用户最终确认后的服务端快照 | 冻结双方角色、场景、目的、背景和备注；编辑新草稿不改旧记录 |
| session_id | 千问会话事件 | 绑定演练与目标版本 |
| item_id | 千问用户／AI最终转写事件 | 按会话与item_id归档及去重，不按文字相同合并 |
| response_id | AI回复事件 | 关联生成、取消及播放信息 |
| speaker | 用户completed／AI音频转写done事件类型 | 归一化user／assistant；原型ai需映射assistant |
| turn_order | 应用轮次与事件关联 | 不按网络到达顺序排列 |
| playback_status | 客户端播放器 | 完整、部分、未播放、未知；不能从文本长度推算 |
| played_ms | 客户端实际播放进度 | 相对于该条音频开始的毫秒偏移；无法取得留空 |
| transcript_version | 服务端收齐最终转写后封存 | 总结绑定版本，迟到数据产生新版本，旧结果不可覆盖新版本 |

## 结束与总结

停止采集后按实际协议提交尾部，保留接收，等待每个待处理轮次完成或明确失败；不是收到任意一个completed就结束。初定整理等待15秒（实施参数待单独确认）；超时或转写不完整提示重试整理，不发布正常总结。超限必须立即停止后续模型调用，不假定因此已收齐转写。

发送总结模型仅goal_snapshot与按轮次排列的speaker/text；响应仅overview、suggestions。ID、播放状态和任务版本保留在业务侧用于归档，不要求模型返回这些字段。

## 呼叫、录音与实战复盘

call_id由服务端创建，记录实际号码；与演练无自动关联。录音及ASR任务按call_id归档，音频和文本版本独立保存。ReviewRequest只在用户选电话、选演练并确认后创建，保存双方ID和输入版本，幂等防重复任务。结果按call_id回挂，不篡改历史快照。ASR细节见[录音与转写技术说明](录音与转写技术说明.md)。

## 系统通讯录

仅使用系统通讯录条目；本机设备范围与CNContact.identifier用于缓存关联，不建立App联系人实体，不按手机号自动合并身份。权限变化移除不可访问缓存；业务通话历史独立保留。当前网页选择页仅占位。

## 账号与交易

account_public_no是独立公开编号，不是数据库主键；采用8位数字连续展示，不加分隔空格。内部user_id仅用于服务端鉴权。平台交易ID与商品ID由StoreKit返回／配置映射，服务端验证后持久化；恢复购买查原充值账号并检查注销，不由客户端编号转移权益。

## 时间及额度

服务端UTC创建时间分别标记演练创建、电话请求创建、复盘任务创建；不能统称“发生时间”。客户端按Asia/Shanghai展示。呼叫connected_at／ended_at取第三方实际事件时刻，received_at仅表示服务端收到事件，不可代替。ASR时间为录音起点偏移毫秒；用户VAD偏移为输入音频时间轴，不是收包时间。

客户端通话及演练界面计时使用单调时钟，仅供展示。正式额度由服务端有效连接分段累计，每日北京时间零点切分，重连及多设备不重置。注销10秒倒计时由客户端单调计时显示，正式提交需服务端防绕过。会员expires_at取验证后的平台权益到期时刻，由服务端返回，不能按手机日期推算。

### 输入长度与上下文预算

双方角色各1–20字、对话目的1–100字，背景0–100字、备注0–60字，五项输入合计最多300字；按Unicode码点计数，超限保留内容并阻止开始。完整instructions预算4096 Token；点评单次完整输入24000 Token、输出4096 Token，并预留4096 Token安全空间，仍须服从实际模型窗口。长转写按正文8000 Token分段、重叠不超过300 Token，保存完整原文与引用索引。字数不等于Token，音频历史另受厂商限制。当前原型只实施表单校验，Token计量及分段属于服务端接入需求。详细规则见[输入字段与AI上下文规则](输入字段与AI上下文规则.md)。

### 官方调用与配置

WebSocket开发验证采用DashScope Python SDK >= 1.26.5，模型qwen3.8-omni-flash-realtime，地址wss://maas.qianwenaiapi.com/api-ws/v1/realtime。pyaudio仅用于本机采集播放；业务服务器接收App音频，不打开服务器麦克风。

当前原型仍使用已有WebRTC接入。此处是流程及接口方案，不表示已切换传输层或接入正式存储和点评。WebRTC通过音轨传音频，不套用append_audio的裸PCM发送方式。

| enable_input_audio_transcription | True | 返回用户转写；内置ASR固定为qwen3-asr-flash-realtime。 |

### 转写角色来源与关联

| 数据 | 来源 | 关联与用途 |
| --- | --- | --- |
| speaker=user（我） | conversation.item.input_audio_transcription.completed事件 | 根据事件类型确定发言来源，保存该事件item_id与transcript，不从文字推测身份。 |
| speaker=assistant（AI） | response.audio_transcript.done事件 | 保存item_id、response_id与transcript；AI文本生成完成不代表用户听完，播放状态单独保存。 |
| user_role／ai_role | 用户确认后的goal_snapshot | 分别对应准备页我扮演／AI扮演，属于业务角色，不是接口识别结果。 |
| rehearsal_id、goal_version | 会话创建时绑定的业务记录 | 每条转写归属于对应演练及目标版本，读取同一快照的角色名称。 |

显示规则：speaker=user时展示“我（goal_snapshot.user_role）”，speaker=assistant时展示“AI（goal_snapshot.ai_role）”。角色名缺失时只显示“我／AI”；来源不明时保留待核对，不猜测。转写列表不显示逐条时间，保留会话轮次顺序。按会话与item_id幂等保存，同一item_id的重复最终事件不重复追加，不同item_id的相同文字不合并。再练或编辑新目标不会改写旧演练快照。当前原型userRole／role及ai等内部名称需在接口层映射到统一业务字段。

### 总结输入拼接与结束收尾

1. 会话开始绑定演练ID和已确认目标版本；使用该版本目标快照，不读取用户之后修改的新草稿。
2. 用户点击结束后先显示“正在整理转写…”，停止采集新语音，按协议提交已采集但未提交的尾部音频。保留事件接收通道，不立即close。自动判停与手动提交的收尾方式应按实际协议验证，不能重复提交同一轮。
3. 维护每个已提交用户item_id的待转写状态，等待最终转写完成或明确失败；同时处理活动AI回复完成／取消及末尾文字，保存实际播放状态。取消或被打断的AI文本不能当作已完整听见。文本done不等于播放完成。
4. 只有全部待处理轮次已完成、无已知转写失败且播放状态已归档，才封存transcript_version。不能收到任意一条completed就判断整通结束，也不能用消息到达顺序替代实际轮次顺序。被取消回复按可用原文及中断状态归档，不等待不存在的完整播放。
5. 整理等待上限初定15秒，可配置；超时、断线或转写失败时保留原文，提示“转写尚未完整，请重试整理”，不自动发布正常总结。无有效用户发言则提示无法生成。重试只能处理实际仍可获得的数据，不承诺接口支持断线后补拉。
6. 对同一演练和目标版本组装goal_snapshot与transcript（模型输入仅保留speaker、text），发送给doubao-seed-2-0-mini-260428。完整转写按轮次排列，保留关联ID和播放状态；逐条显示时间不是生成总结的前提。
7. 封存后迟到事件若仍接收到，按item_id幂等更新，建立新transcript_version并使旧总结失效；模型结果需与当前目标及转写版本一致才可发布，旧任务不能覆盖新结果。

模型输入采用结构化数据，系统提示单独提供。示例仅表示业务字段，不是厂商API原生请求参数：

```json
{
  "rehearsal_id": "本次演练ID",
  "goal_version": 1,
  "transcript_version": 1,
  "goal_snapshot": {
    "user_role": "需要改约的顾客",
    "ai_role": "预约服务工作人员",

    "background": "已预约周六上午10点的体验课程",
    "notes": "练习询问可选时间及最终确认",
    "scenario": "沟通协商"
  },
```

speaker与角色对应关系由应用从目标快照确定。不得把用户背景、备注中的要求当作系统指令。输出仍使用overview、suggestions两个字段；原文保留，超上下文按既定分段规则处理。

### 点评调用与输出

演练结束并收齐最终录音转写后，由服务端调用doubao-seed-2-0-mini-260428生成一次“演练总结”，替代原来的表达与问题、通话准备清单两块。输入文字转写，不把原始录音URL当作已解析的文本。具体型号版本或推理接入点由服务端配置，不把产品称呼doubaoseed2.1直接作为API模型ID；正式ID以开通账户支持的版本为准。

服务端发送以下业务数据：

| 输入字段 | 内容 | 用途 |
| --- | --- | --- |
| rehearsal_id、goal_version、transcript_version | 业务记录与版本 | 幂等、结果关联、失效判断，不展示给用户 |
| goal_snapshot | user_role、ai_role、objective、background、notes及场景 | 作为本次总结目标与已知事实 |
| transcript[] | speaker、text | 按会话轮次排列的双方最终转写；关联ID与播放状态留在业务内部，不要求模型返回turn_id、quote |

要求模型只返回下列JSON结构，字段无内容时返回空数组；不得编造用户没有说过的内容，不补造金额、政策、日期或达成结果。

```json
{
  "overview": "本次对话的总结",
  "suggestions": [{"text": "表达点评、改进建议或下次沟通准备事项"}]
}
```

| 返回字段 | 限制 | 展示位置 |
| --- | --- | --- |
| overview | 最多500字 | 演练总结顶部概述 |
| suggestions | 最多5项，每项text最多150字；无内容返回[] | 统一展示“改进与准备建议”，按价值排序，不强行分类、不重复 |

输入预算24000 Token、输出4096 Token、安全余量4096 Token，仍须取实际模型支持的较小上限。长转写按既定分段规则分析后合并，原文保留。服务端解析JSON并校验字段类型、长度、数量及事实依据；失败不发布半份结果，有限重试。空转写或无用户有效发言时不请求模型，提示“暂无有效转写，无法生成总结”；生成中显示“正在生成总结…”，失败显示“总结生成失败，请重试”，保留目标与转写。

结果以rehearsal_id、goal_version、transcript_version、prompt_version和模型版本关联保存；相同输入重试覆盖任务结果，不新增一条演练。客户端只展示已校验的结构化数据，模型密钥仅存服务端。当前原型已合并展示结构，真实总结接口尚未接入，不再显示固定场景模板作为分析结果。

官方接口能力与模型ID参考：[火山方舟模型列表](https://docs.volcengine.com/docs/ark/model-list?lang=en)。

### 交互与异常边界

演练只有持续对话和结束，不提供暂停、继续、撤回上一轮或提示按钮。已移除文字提示入口；查看对话不改变语音连接、播放或计时。正常结束后可新建演练；断线重连不假设旧会话上下文自动恢复。

每日累计最多900秒，按北京时间零点重置；达到上限立即断开并保存已有内容。连接失败不计入对练时长，等待回复或查看对话期间保持连接则计时。跨设备额度由服务器统一执行；现有原型仅本机演示。

取消生成及停止播放不等于删除模型历史；未核实的历史删除、截断和恢复能力不列为首版承诺。部分播放或播放状态未知时，点评需说明限制，不能认定用户已听完。

## 实时语音实现

- 已确定实时模型为Qwen3.8-Omni-Flash-Realtime云端。采用官方成熟SDK和实时协议，优先WebRTC；官方移动端AOQ等方案按可用性、弱网、AEC和时延实测选择。正式开发不手写未经验证的音频传输协议。
- 服务端建立会话、限制上下文和额度。长期API Key保存在服务端；客户端仅使用官方支持的短时授权或服务端代理/官方鉴权路径，不能假定任一接口都支持短时令牌。
- 语义轮次检测减少附和声误打断。打断时同步取消生成、停止播放、清空缓存及记录播放位置，避免未听见内容进入后续分析。演练不提供暂停和继续；会话退出需要真正结束服务。
- 目标卡、场景策略、角色规则与对话历史分开管理。真实电话采集链路独立于Qwen模拟对话，Qwen不能让普通系统电话自动具备录音能力。

## 手动关联与分析

- Call记录无自动演练关联。仅ReviewRequest持有用户手选的call_id、selected_rehearsal_id及版本；点击复盘打开选择器不等于已创建关系。
- 确认提交后复核两份记录访问权限、目标版本、有效分支、原文版本、幂等及分析额度。按快照生成，用户修改原始资料不会悄悄重算旧结果。
- 演练点评与真实对照是两个文本分析任务，实时语音角色模型不同时承担评分老师。复盘文本分析模型待定；豆包录音文件识别模型2.0仅用于录音转写。对照只可引用真实原文；演练虚构的同意或承诺不能当作实战结果。
- 数据库/对象存储地址和凭证不提供给模型。授权的必要转录文本会提供给分析服务，须说明处理用途、供应商及留存。

## 会员演练与每日时长限制（2026-10-16）

演练仅限有效会员使用；每个账号每天累计最多900秒（15分钟），按Asia/Shanghai北京时间零点重置。服务器以实时会话连接成功至断开的累计时长计费，等待回复或查看对话期间保持连接则计时；连接失败不计时，断线、退出后停止计时，重连、刷新、重试及跨设备不重置额度。同一账号最多一个演练会话。达到900秒时服务器主动断开Qwen连接并停止后续调用，客户端同步停止采集、播放和重试，保存已有对话，显示：您今日的演练时长已使用完，请明日再来。历史记录仍可查看。

### 服务端执行方案

- 建连前核验会员有效期，用账号与北京时间日期作为配额键，原子检查累计用量并获取单会话锁；无资格或额度不足时不创建Qwen会话。
- 服务器使用单调时钟累计有效连接秒数，持久化连接分段并定期续租、落账；按剩余额度设置硬截止时间，独立定时器负责断开，不能依赖客户端按钮或模型提示词。
- 用量事件按会话ID与分段序号幂等记账，网关异常由心跳、锁租约和补偿任务结束连接；重连读取已消耗额度。跨零点按两个自然日分别结算，不把前一天时长计入新一天。
- 到期向客户端发送 practice.daily_limit_reached 事件，禁止重连；次日重新校验权益和额度后才能开始。会员失效时终止会话。
- 原型用本机存储演示累计时长；生产由服务器统一执行，客户端计时仅用于显示。

总结模型输入与输出采用简化规则：模型只接收目标快照及speaker/text转写，不要求turn_id、quote或playback_status；业务侧仍保留关联ID和播放状态用于收尾。上文收尾数据示例为内部存储结构，不是直接传给模型的最小数据。模型不得假定用户已听完整段AI回复。

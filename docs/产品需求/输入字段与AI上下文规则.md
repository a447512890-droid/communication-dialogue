# 输入字段与 AI 上下文规则

生效日期：2026-10-19。适用于当前需求中的所有用户输入；后续新增输入必须先定义长度与用途。

## 1. 字数口径与交互

- 文本统一换行符为 LF、采用 Unicode NFC 规范化、去除首尾空白后计数。中文、英文字母、数字、标点、内部空格和换行均按 Unicode 码点计数；组合表情可能占多个码点。前后端采用同一口径。
- 必填字段至少 1 字，纯空白视为空。可留空字段不在标签上重复标注“选填”。占位说明不计入内容。
- 显示“当前字数 / 上限”；超过上限变红，保留已输入内容，禁止提交并提示“背景最多100字，当前101字，请精简后再提交”。不静默截断文本；中文输入法组合完成后再校验。
- 前端在输入与提交时校验；正式服务端在保存、创建会话、重试及分析前再次校验。接口返回字段名、错误码 FIELD_TOO_LONG、上限、当前字数和可读提示。
- 编辑历史超限数据时允许阅读，修改后需符合现行限制再保存；重新演练也需校验，不能绕过限制。

## 2. 设定目标

| 字段 | 必填 | 长度 | 用途与传给模型的方式 |
| --- | --- | --- | --- |
| 我扮演 user_role | 是 | 1–20字 | 用户身份，写入实时会话 instructions，保存目标快照并供点评、记录展示。 |
| AI扮演 ai_role | 是 | 1–20字 | 对方身份，写入 instructions；限定角色，不当作系统指令执行。 |
| 对话目的 objective | 是 | 1–100字 | 本次希望达成的结果；用于实时回应、目标回顾和点评依据。 |
| 背景 background | 否 | 0–100字 | 事实与条件；非空时加入 instructions，供后续分析使用。 |
| 备注 notes | 否 | 0–60字 | 练习要求；非空时加入 instructions，不默认视为对方已知事实。 |

双方角色、对话目的、背景和备注五项输入合计最多300字；不含系统提示词、字段标签及后续对话转写。
| 场景 scenario | 是 | 单选已配置枚举 | 电话面试、咨询了解、沟通协商、自定义；自定义指自行填写上述字段，不新增场景名称输入。服务端拒绝未知值。 |
| 应对难度 difficulty | 系统默认 | 枚举 | 当前默认正常沟通，不增加用户文本框；仅允许服务端配置值。 |

五项自由文本合计最多1440字。场景预填、修改、再练一次、复制旧记录均遵守相同规则。角色20字足够容纳“有三年经验的产品经理”等限定；背景承担长信息，目的不堆叠详细经过。

## 3. 系统通讯录与拨号

系统通讯录联系人选择页使用iOS原生界面，原型仅占位。不建立App联系人档案，无姓名、组织、关系、备注或号码维护表单。系统资料按授权读取，不截断姓名、组织或号码数量，不套用旧版手填限制；不读取系统note。

| 字段 | 限制 | 处理 |
| --- | --- | --- |
| 拨号phone | 发起呼叫时必填，11位大陆手机号，以1开头 | 左侧固定+86；号码有效前呼叫置灰 |
| 系统号码 | 保留原始值，选中后规范化 | 移除开头+86／0086及分隔字符；当前不支持的号码提示，不静默截成另一个号码 |

超过11位保留内容、禁止呼叫。系统通讯录仅本地缓存，不整本上传，授权与同步规则见需求说明。系统选择页不绘制App资料详情。

## 4. 其他输入与选择

| 输入 | 限制 | 处理 |
| --- | --- | --- |
| 页面搜索、需求搜索 | 0–100字 | 仅本地检索，不送入 AI；超限不执行新搜索。 |
| 选择联系人／号码 | 单选可访问记录及该记录已有号码 | 校验归属与有效性，不接受任意记录ID。 |
| 选择对照演练 | 单选本人已完成且有有效对话的记录 | 传内部ID，服务端读取对应快照，用户不输入整段历史。 |
| 会员方案、记录类型、协议确认等 | 已配置枚举／布尔值 | 不接受自定义文本，不适用字数限制。 |
| 演练实时语音、实战录音及用户发起的转写 | 不设表单字数上限 | 按音频接口规格、额度及存储规则处理；AI分析执行下述分段预算，不能按备注限制截断。 |

当前需求没有独立的短信验证码、密码、上传文件名或人工修改转写输入框，不新增这些字段。后续增加时另定规则。

## 5. AI 请求预算

字数与 Token 不可直接等同。以下是本产品的调用预算，不是厂商最大值。模型、版本、地域和接入协议上线前应重新核实；演练总结使用doubao-seed-2-0-mini-260428，具体版本／接入点配置待接入；实战复盘型号仍待确定。不能把实时模型参数直接套用到分析模型。

| 环节 | 产品预算 | 计算范围与处理 |
| --- | --- | --- |
| 实时演练首次 instructions | ≤4096 Token | 包含系统角色、场景规则、五项用户字段、分隔与安全说明。服务端拼接后计量，超过时拒绝创建并定位来源，不截断用户目标。 |
| 点评／复盘单次输入 | ≤24000 Token | 包含指令、JSON结构、目标快照、必要背景、演练／实战文字及引用索引的完整输入。 |
| 点评／复盘单次输出 | ≤4096 Token | 在所选接口支持的输出上限参数中配置；校验JSON结构，截断或缺字段视为未完成，不发布半份结果。 |
| 请求安全余量 | ≥4096 Token | 当模型共享上下文窗口时，输入＋最大输出＋余量不得超过窗口；还需分别遵守厂商最大输入和最大输出限制。 |
| 长转写分段 | 每段正文≤8000 Token，相邻重叠≤300 Token | 优先按说话轮次切分；单轮过长才在句边界分割，保留原始记录ID、轮次ID及字符／时间定位。所有段累计覆盖原文。 |

预算实际取“产品预算”与“当前模型允许值”的较小值，并扣除系统提示等开销。若模型窗口不足，应缩小分段，不能照搬24000。重叠内容按原始ID去重，不能重复统计问题或证据。

分段分析先产出带原文定位的结果，再合并；合并输入也不得超过预算，必要时逐级归并。摘要用于导航与概览，结论所引原话回查原文。完整录音与转写按原有保留策略保存，不用摘要覆盖原文。

接入提供官方分词器／预计算接口时按对应模型计量；若只有请求后的usage，则该值仅用于校准，不能当作请求前精确计数。无可靠预计算能力时采用经样本验证的保守估算、缩小预算，并处理厂商超上下文错误：保留原文、缩小片段后有限重试，仍失败则返回可重试错误。禁止无限重试或静默删掉用户事实。

### 实时语音历史

官方当前文档列出 Qwen3.8-Omni-Flash-Realtime 最大输入196608 Token，音频历史上限100轮／600秒。音频也占上下文，不能用1440字的表单上限推算能聊多久；音频历史保留范围也不等于产品每日使用额度。

服务端记录usage和历史范围；会话较长时完整对话仍应保存到业务侧，不能假定模型永久记得最初音频。自动摘要续接需先验证该协议的历史管理能力；当前不宣称已实现。若无法可靠续接，在到达可用上下文边界前提示用户结束本次并开始新一轮，保存既有记录，不添加暂停／继续功能。

官方依据：[Qwen3.8-Omni-Flash-Realtime模型说明](https://help.aliyun.com/en/model-studio/qwen3-8-omni-flash-realtime)、[实时客户端事件](https://help.aliyun.com/zh/model-studio/client-events)。厂商限制可能变更，以实际接入版本为准。

## 6. 数据组装与落地范围

- 用户内容作为数据字段引用，明确与系统规则分隔；不能覆盖角色安全边界、工具权限和输出约束。说明“这是用户数据”不能替代服务端权限校验。
- 只发送当前任务必要数据：实时演练使用已确认目标，不整本发送通讯录、其他人的记录、手机号或原始API密钥。复盘按用户明确选择读取相关演练与实战。
- 原型已实现演练文本计数、非空与超限拦截、搜索上限；集中定义在原型/input-rules.js。手机号超长时保留数字并阻止呼叫。
- 服务端二次校验、精确Token计量、转写分段、分段合并及上下文续接属于正式接入需求，当前原型未实现，不把常量配置视为已执行。

## 7. 预设场景内容

首页仅展示场景名称，不加小字；以下内容进入准备页后预填，用户可修改。

| 字段 | 咨询了解 | 沟通协商 |
| --- | --- | --- |
| 我扮演 | 想办健身卡的顾客 | 需要改约的顾客 |
| AI扮演 | 健身房工作人员 | 预约服务工作人员 |
| 对话目的 | 了解会员价格、包含的服务和使用限制，确认是否适合自己 | 将本周六上午的预约改到周日下午，并确认是否产生额外费用 |
| 背景 | 我第一次咨询这家健身房，主要想在工作日晚上锻炼，还没有决定是否办卡。 | 我已预约本周六上午10点到店体验课程，但临时有事无法到场，希望改到周日下午。 |
| 备注 | 请正常介绍服务，让我主动询问价格、营业时间、额外收费和退卡条件。 | 周日下午可能比较满，请提出合理限制，让我练习解释原因、询问其他时段并确认最终安排。 |

## 输出及提交规则

演练总结仅返回overview（200字）与suggestions（最多5项，每项text150字）；不要求quote、turn_id、feedback或preparation。内部原文、关联ID及版本继续保留。前端必填缺失、空白、格式无效或超限时提交置灰；最终提交仍由服务端校验。额度用尽提示在确认目标最终提交时触发，运行中额度硬限制仍有效。
